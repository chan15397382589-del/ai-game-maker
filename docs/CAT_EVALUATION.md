# 最终数字游戏作品 CAT 评价系统

## 评价单位与口径

- 一个评分批次对应同一次创作任务；每位被纳入的学生只能冻结一件最终作品。
- 总体创造力由专家整体判断，取 1–5 的整数。新颖性、设计成立性、精致性与契合性仅作为判断参考，不另行要求打分。数据库保留旧的可空维度列，便于兼容已有结构；正式研究结果只采用总体分。
- 评分页逐级展示原评价表的文字锚点。原文末尾“专家评分记录表示例”把总体创造力误写为 1–7；逐级评分标准实际为 1–5，且本项目按用户确认统一采用 1–5。
- 试玩状态单独记录：可运行、部分可运行、无法正常运行、无法查看。无法查看时总体分留空并记录原因；不能记为 0 分。
- 建议 3–5 位专家独立评分。可先建立登录号 1–5 的独立 Supabase Auth 账号（系统内部以保留的 `.invalid` 地址满足 Auth 邮箱字段），暂不填写姓名；正式分配评分前必须核实并补录专家实名，形成账号、实名、评审编号一一对应。同一专家可被分配到多个批次，但同一作品只允许其提交一份评分。系统保存每人的原始分、文字依据、提交时间和量规版本；正式提交后锁定。账号共用无法仅靠技术识别，须通过评审协议明确禁止。
- 与 D0–D7 对话过程编码、任务表现评价相互独立。作品均分不能直接解释为学习成效或组别因果效应。

## 操作流程

1. 先备份 Supabase 数据库，再人工审查并执行 [`supabase-cat-evaluation.sql`](../supabase/migrations/supabase-cat-evaluation.sql)。该迁移只新增 CAT 表与约束，不回写历史作品或消息。本仓库不会自动执行生产迁移。
   如果此前已执行过 CAT 初稿迁移，更新后的脚本会补加专家实名等列，但 `CREATE TABLE IF NOT EXISTS` 不会自动补齐旧表全部约束；必须先核对实际表结构。旧专家账号的实名保持未知，须经核实后在管理页补录，不能用 R01 等编号代替真实姓名。
2. 管理员进入 `/admin/cat`，创建评分批次，选择年级和任务。
3. 管理员可先创建登录号 1–5 的独立账号，无须邮箱或专家真实姓名；系统会处理旧版 `on_auth_user_created` 触发器自动生成的误入学生表记录。本次已按用户要求设置共同初始密码，密码不写入仓库；正式评分前建议分别更换密码并确认每个账号的实际使用者。正式分配评分前补录并核实每位专家真实姓名。专家从 `/cat/review` 输入登录号及密码，不能与学生或管理员身份共用。
4. 在逐人清单里核对 `projects`、`conversations` 和 `game_snapshots` 三种候选来源的内容、产生及更新时间、对话关联、研究原始记录与是否存在事后修复。候选记录不自动等于学生最终提交；管理员须逐件核实并手动冻结一件最终版。冻结快照含完整 HTML、来源类型与 ID、时间戳、SHA-256 和核实说明，不能更改。
5. 检查未冻结学生。此状态只表示“尚未核实并冻结”，不能直接解释为“无作品”。只有对话中的代码或历史数据不完整时，应先做来源核验；不能把最新对话代码或快照自动当作最终作品。
6. 分配 3–5 位专家；批次尚未开放且未生成评分任务时可移除误选专家，不删除其账号。确认作品内没有可识别的姓名、班级、组别等信息后开放盲评。专家只看到随机作品编号和隔离预览，不能查看学生对应关系或其他专家分数。管理员可按账号查看提交进度。
7. 专家可保存草稿、修改本人密码；正式提交时校验量规与缺失规则，提交后不可改。所有任务提交后管理员结项，导出“专家原始评分 CSV”“学生汇总 CSV”，以及单独的“专家账号索引 CSV”。账号索引含专家实名和邮箱，属于敏感信息，应与学生评分文件分开受控保存。CSV 以 UTF-8 BOM 编码，并防止表格公式注入。

## 一位专家一个账号：数据关系与权限

| 层级 | 唯一性/用途 | 专家可见内容 |
| --- | --- | --- |
| Supabase Auth 用户 | 独立登录号映射到内部 Auth 邮箱、独立密码和 `auth_user_id` | 仅本人登录态 |
| `cat_reviewers` | `auth_user_id` 与评审编号均唯一；实名可先留空，分配前必须补录 | 本人评审编号 |
| `cat_batch_reviewers` | 一个专家在一个批次只分配一次 | 自己的开放批次任务 |
| `cat_scores` | `(artifact_id, reviewer_id)` 唯一；每件作品每位专家最多一份评分 | 仅本人的草稿与已提交评分 |
| `cat_artifacts` | 每名学生每批次一件冻结作品，与账号分离 | 随机作品编号和隔离预览 |

评审接口从登录令牌提取 Auth 用户 ID，再查该用户唯一的专家记录；不接受前端传入的“评审者 ID”来决定权限。专家账号若同时出现在学生/管理员用户表，会被拒绝。数据库开启 RLS，评分数据只经身份校验后的服务端访问。实名—编号映射及逐专家进度仅管理员可见；原始评分导出使用编号，不把实名传到专家端。

## 数据质量与后续分析

- 汇总 CSV 覆盖该年级当前学生名单，未冻结者保留单独状态和空白分数；不能把空白当作 0。名单是导出时的当前 `users` 表快照，若研究样本不是全年级，须按研究纳入标准另行筛选并留痕。
- 汇总表提供各学生有效评分人数、总体创造力均值与样本标准差，原始 CSV 保留专家原分。正式分析前应检查评分者一致性并报告所采用的 ICC 类型、置信区间及异常/缺失处理规则；系统不自动声称一致性合格。
- 不以评分页面的“可运行”直接证明学生经历了完整设计学习。作品质量与对话过程之间的对应，仍需以学生 ID、作品来源及冻结版本为可追溯连接。
- `src/app/api/admin/projects/route.ts` 的作品审核列表取自对话文档的最新代码，不代表正式最终提交版本；CAT 评分同时呈现三种候选来源，但必须人工核对最终版本，不能只按时间顺序选取。
